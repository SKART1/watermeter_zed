# План улучшений Watermeter ZED

16 ноября 2026 года. Работаем по трём задачам, по порядку.

## 1. Общий OR протечки

Мокро, когда хотя бы один вход мокрый. Сухо, только когда оба входа сухие. Состояния берём с учётом существующей фильтрации контактов.

Программная часть выполнена: кандидат v2.0.06 прошёл тесты, независимое ревью и сборку. На датчик он ещё не установлен; [результаты и образ](or-fix.md).

Проверяем обе пары по очереди, короткие импульсы и основной проблемный случай: A остаётся мокрой, B намокла и высохла — общая тревога сохраняется. Затем проверяем зеркальный случай и высыхание последней мокрой пары.

## 2. Состояние при отсутствии связи

Датчик определяет состояние контактов независимо от доступности сети. После восстановления связи передаёт актуальное состояние без нового касания. Если за это время всё высохло — передаёт «сухо».

Возврат координатора или Z2M не всегда вызывает переподключение датчика. Поэтому при необходимости добавляем повторную отправку статуса в рамках этой задачи. Повтор статуса не должен автоматически повторять команды реле, особенно `toggle`.

Проверяем намокание и высыхание без связи, затем возврат сети с переподключением и без него. Результат — новое сообщение о текущем состоянии, а не старое значение из кеша.

## 3. Периодический поиск сети вместо бессрочного сна

Предлагаемый вариант: после 30 минут без сети засыпать на 15 минут, затем просыпаться и ограниченное время пытаться подключиться. При неудаче повторять цикл. После подключения передать актуальное состояние по пункту 2.

Контакты должны сохранять возможность разбудить датчик раньше таймера. Периодическое пробуждение должно работать и при неизменно мокрых контактах.

Проверяем выход из сна, повторный поиск и восстановление состояния после возврата сети. Интервал 15 минут пока предлагаемый: он влияет на расход батареи и задержку обнаружения вернувшейся сети.

## Как выполняем

Для каждой задачи: программная проверка → независимое ревью и сборка → испытание одного контрольного датчика. Для OR сначала воспроизводим ошибку реальным старым обработчиком, затем проверяем исправленный теми же сценариями.

Существующий интерфейс Z2M и поведение управления кранами сохраняем. Перед физическим испытанием учитываем реальные биндинги: снятый с места датчик всё ещё может управлять кранами.

Программные сценарии OR и порядок запуска описаны в [тестах обработчика](../tests/leak/README.md).

## На будущее

Эти улучшения не входят в ближайшие три задачи:

- Повторы команд реле.
- Отдельные сущности протечки A/B.
- Усиление сохранности данных при прерывании OTA.
- Сервисный режим для удобной диагностики.
